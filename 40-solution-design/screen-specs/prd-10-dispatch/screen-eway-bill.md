# Screen — e-Way Bill

**Module:** PRD-10 Dispatch · **Demo spine:** step ⑯.

The generated e-Way Bill — **33 fields in the government's own structure**: details, Part A, Part B,
goods.

> **This is a government form, not a Phlo form.** Its shape is fixed by the GST system, documented
> field-by-field in [obs-03 §8](../../../10-observations/obs-03-field-catalog.md). Rendering it in a
> different structure would make it unrecognisable to the people who check it — and a truck stopped
> without a valid e-Way Bill is a real operational failure, not a cosmetic one.

**An inter-plant transfer needs one too.** `REQ-IM-005` sends a different-GSTIN transfer out on a
sale-purchase invoice, and goods above ₹50,000 moving on the road need an e-Way Bill regardless of
whether the counterparty is a customer or another Pyramid unit.

## 2. UX Layout

Four blocks, in the government's order.

```
┌───────────────────────────────────────────────────────────────────────────┐
│ e-Way Bill  EWB-9921 4471 2210         [Print]  [PDF]  [Back]            │
│ ⏱ valid until 21/08/2026 23:59 · 2 days remaining                         │
├───────────────────────────────────────────────────────────────────────────┤
│ ── DETAILS ──────────────────────────────────────────────────────────     │
│  Generated 19/08 08:12 by 24AAACP1234F1Z5 · Mode Road · ~31 km            │
│  Type Outward-Supply · Transaction 1-Regular · IRN a4f2…                   │
├───────────────────────────────────────────────────────────────────────────┤
│ ── PART A ───────────────────────  │ ── PART B — VEHICLE ─────────────    │
│  Supplier  24AAACP…  Unit VII      │  Mode      Road                      │
│  Recipient 27AAKFS…  Ambernath MH  │  Vehicle   GJ16BX7742                │
│  Document  INV-8834 · 19/08        │  From      Bharuch, GJ               │
│  Value     ₹2,62,845               │  Entered   19/08 08:12               │
│  Reason    Outward-Supply          │  CEWB      —                         │
│  Transporter  Pyramid Technoplast  │  Multi-veh —                         │
├───────────────────────────────────────────────────────────────────────────┤
│ ── GOODS ────────────────────────────────────────────────────────────     │
│  HSN 39231010 · HDPE Drum 210 L · 300 NOS · ₹1,95,000 · 0+0+18+0+0        │
└───────────────────────────────────────────────────────────────────────────┘
```

- **Validity countdown** at the top — the field that matters operationally.
- **Details, Part A, Part B, Goods** in the government's grouping.

### Validity is the only live element

`Valid Upto` is **distance-based** (obs-03 §8 field 4). A truck arriving after expiry is a compliance
problem at a checkpoint, not a back-office one — so the countdown sits in the header rather than buried
in a details block.

`[UNKNOWN: Pyramid's typical delivery distances. The one real outbound movement in evidence is **31 km**
— U-VIII Khanivali to Spectrum Packaging, Bhiwandi (as-is model §3.9). Nine plants across two states
suggests a much wider spread, and validity rules change with distance.]`

## 3. Data Points Displayed

### Details — 10 fields

e-Way Bill No. (12 digits) · Generated Date · Generated By (GSTIN) · **Valid Upto** · Mode ·
**Approx Distance** · Transaction Type · Type (Outward/Inward) · Document Details · **IRN**.

### Part A — 11 fields

GSTIN of Supplier · Place of Dispatch · GSTIN of Recipient · Place of Delivery · Document No. ·
Document Date · Transaction Type · Value of Goods · HSN Code · Reason for Transportation · Transporter.

### Part B — 7 fields

Mode · **Vehicle / Trans Doc No & Dt** · From · Entered Date · Entered By · CEWB No. · Multi Veh. Info.

### Goods — 5 fields per line

HSN Code · Product Description · Quantity · Taxable Amount · **Tax Rate** in the government's own
format: `CGST+SGST+IGST+Cess+Non.Advol`.

### Where each field comes from

| Block | Source |
|---|---|
| Supplier GSTIN, place of dispatch | The dispatching plant (`locations`) |
| Recipient GSTIN, place of delivery | `Party`, consignee |
| Document no. and date | The **invoice** (prd-11), or the challan where no invoice exists yet |
| Value, HSN, tax rate | Dispatch lines × prd-09 rates |
| **Vehicle, transporter** | prd-12 fleet assignment |
| Transporter name | **Pyramid itself** on own-fleet dispatches — proc-02 Flow A: Pyramid is the carrier outbound |

**Part B cannot be filled without prd-12.** That is the hard dependency named in this module's
boundaries: no vehicle, no e-Way Bill, no legal movement.

### Three government facilities are not modelled

Part B update, validity extension and cancellation are all real e-Way Bill operations with time limits.
**None exists in prd-10's event list.** A vehicle breakdown mid-journey is exactly the case that needs
Part B updated, and it is not an edge case across nine plants and ~100 trucks.

## 5. Validations

Generation-time, surfaced here if they failed:

| Rule | Message |
|---|---|
| Taxable value > ₹50,000 | Below threshold, no e-Way Bill is generated — stated, not silently skipped |
| Supplier and recipient GSTIN required | "Recipient has no GSTIN. An e-Way Bill cannot be generated." |
| **Vehicle number required** | "Part B needs a vehicle. Assign one in fleet management." |
| Distance required | "Approximate distance is needed to compute validity." |
| HSN required per line | "No HSN on WMD-035." |
| Document reference required | "No invoice or challan to reference." |

## 6. Conditional States

| State | What the user sees |
|---|---|
| **Loading** | Document skeleton |
| **Generated, valid** | Full document; countdown in green |
| **Expiring soon** | Amber countdown under ~6 hours: "Valid until 23:59 today." |
| **Expired** | **Red banner: "This e-Way Bill expired on 21/08. The vehicle should not be moving under it."** The bluntest state in the module, because the consequence is a stopped truck |
| **Below threshold** | "Not required — ₹38,400 is below ₹50,000." No document rendered |
| **Vehicle not assigned** | Part B empty with an amber block: "Assign a vehicle before this movement." Generation blocked |
| **No invoice yet** | Document reference falls back to the challan, with a note. `[UNKNOWN: whether Pyramid raises the invoice before or after the e-Way Bill. obs-03 shows the e-Way Bill referencing an invoice number, which suggests invoice first]` |
| **Inter-plant, cross-GSTIN** | Type reads Outward-Supply; a note explains it is a stock transfer requiring an invoice (prd-06 `REQ-IM-005`) |
| **Multi-vehicle** | `Multi Veh. Info` populated. `[UNKNOWN: whether Pyramid ever splits one consignment across trucks]` |
| **Portal integration failed** | `A-DS-03` assumes Phlo generates it. If generation is by API and it fails, the dispatch is **blocked, not degraded** — unlike carrier tracking, this is a legal requirement. `[UNKNOWN: API or export — prd-10 OQ5]` |
| **Restricted** | Viewable and printable by dispatch and plant roles — it travels with the truck |

## Open Questions

1. **API to the government portal, or data export?** prd-10 OQ5, `A-DS-03`. It decides whether a
   dispatch can be blocked by an integration failure — and unlike carrier tracking, there is no manual
   fallback that is legal.
2. **What distances does Pyramid deliver over?** One 31 km movement is the only evidence. Validity
   depends on it.
3. **Invoice before e-Way Bill, or after?** obs-03's sample references an invoice number, implying
   invoice first — but nothing confirms the sequence.
4. **Are Part B updates, extensions and cancellations needed?** All three are real facilities and none
   is modelled. A breakdown across nine plants is not an edge case.
5. **Does Pyramid ever consolidate (CEWB) or split across vehicles?** Both fields exist on the form.
